# SAAQ — what the rules cannot tell you

Read by the orchestrator and the adjudicator, never by an extractor.

Judgement only. Every rule lives in pack data and is applied by code before you see
anything; where this page and the data disagree, the data is right.

## Expect no forms

Art. 83.15 fills these files with correspondence: letters with no template, no serial and
no fixed layout. A CNESST file is largely forms; this one is largely prose.

Two consequences. Classification is content-first — a document is what it says it is, and
waiting for a form serial that never comes leaves most of the file unclassified. And the
template registry will match almost nothing here, which is expected rather than a failure:
the deterministic path is thinner and more of the work is reading.

## The vocabulary is genuinely different

The milestone is **{vocabulary.milestone}** and the impairment measure is
**{vocabulary.impairment}**. These are not synonyms of the CNESST words — they are this
regime's own terms, and a chronology that borrows the neighbouring regime's vocabulary
reads as though nobody checked which statute applies.

Watch for the reverse leak too. A treating physician who also does CNESST work will write
the CNESST milestone on a SAAQ file out of habit. That is a fact about the document, so
transcribe what it says; it is not licence to translate the regime.

## No opinion binds

Unlike CNESST, this regime has no binding-treating-opinion tier. A treating report and an
insurer's expertise are both contestable, and neither outranks the other by its source
alone. Do not import the CNESST hierarchy: it would overstate every treating report in the
file.

## What to escalate rather than decide

- A document that names the CNESST milestone on a SAAQ file — habit, or a genuinely mixed
  file the screener should have re-tagged?
- Any impairment field, which this pack cannot yet read deterministically. The plan lists
  those gaps before the work is approved; do not fill one from inference.
