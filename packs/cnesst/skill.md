# CNESST — what the rules cannot tell you

Read by the orchestrator and the adjudicator. Not by an extractor: an extractor sees one
report and should reason about that page, not about the case.

This page holds judgement only. Every rule — which class, which date, which filter — lives
in pack data and is applied by code before you see anything. If this page and the data ever
disagree, the data is right and this page is a bug.

## Several claims can live in one file

A file is not one accident. A 2022 claim framed as a **rechute, récidive ou aggravation**
of a 1990 event pulls the 1992–96 reports into scope, and they are evidence, not clutter.

So when a document looks too old to belong: do not reason from its date. Ask whether the
file asserts an RRA relation anywhere. If it does, old reports are in scope by that
relation, and the engine has already attributed each unit to a claim event with its reason
attached — read the reason before overriding it.

The reverse error is worse. Quietly dropping a 1992 report from a file that turns on
whether the 1990 injury ever consolidated removes the evidence the case is about.

## Who obtained a report changes what it is worth

Under this regime the treating physician's opinion carries a binding tier unless it is
displaced. An expertise is the instrument that tries to displace it.

When a treating report and an expertise disagree, that disagreement is the finding. Surface
both with their dates and who procured each. Do not resolve it, do not average it, and do
not prefer the more recent one because it is more recent — which of them governs is a legal
question and the file exists to argue it.

## What to escalate rather than decide

- A unit whose documents point at two different claim events.
- An impairment rated in one report and absent from another covering the same period.
- A form revision the registry does not recognise. Reading the wrong coordinates silently
  is worse than reporting that the form is unknown.
